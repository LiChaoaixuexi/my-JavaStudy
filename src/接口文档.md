# 基于STM32的居家智能灯监控系统应用层需求分析与设计文档
## 一、需求分析阶段
### （一）项目目标
应用层作为系统面向用户的核心交互层，需基于已完成的感知层（STM32+传感器+执行器）与传输层（ESP8266+MQTT），搭建“前端可视化交互+后端数据处理”的完整闭环。核心目标是实现灯光状态实时监控、远程控制、数据存储分析及异常告警，为用户提供便捷、稳定、安全的居家智能灯管理体验，同时支撑系统全链路数据流转与功能扩展。

### （二）用户需求
#### 1. 核心功能需求
- 状态可视化：实时展示灯光开关状态、当前亮度值（5%-100%）、环境光照强度（lux），数据更新延迟≤200ms，与传输层指标对齐。
- 远程控制：支持灯光开关操作、亮度无级调节（5%-100%）、预设场景切换（阅读/睡眠/观影），指令下发后响应反馈≤300ms。
- 数据查询：提供历史数据查询功能，支持按时间范围（今日/本周/本月/自定义）查看光照强度、亮度调节记录，数据保留时长≥30天。
- 异常告警：当传感器故障、通信断连、亮度异常（超出设定阈值）时，通过前端弹窗、消息提示等方式告警，同时记录告警日志。
- 个性化设置：支持用户自定义亮度阈值（触发自动调节）、场景参数（如阅读模式亮度70%）、数据更新频率，设置项自动同步至数据库。

#### 2. 性能需求
- 并发支持：同时支持≥10个客户端（手机APP+Web端）连接，无指令冲突或数据延迟叠加问题。
- 响应速度：前端页面加载≤2s，控制指令下发至状态反馈≤500ms，数据查询结果返回≤1s。
- 稳定性：系统持续运行72小时无崩溃，数据传输无丢失（损耗率≤0.2%），与传输层稳定性指标一致。
- 兼容性：前端支持主流浏览器（Chrome、Edge、Safari）及Android/iOS移动端，后端支持跨平台部署（Windows/Linux）。

#### 3. 安全需求
- 身份认证：用户需通过账号密码登录系统，支持密码加密存储（MD5+盐值），防止明文泄露。
- 权限控制：仅登录用户可操作控制功能，游客仅支持查看公开演示数据（可选），不同用户账号数据隔离。
- 数据安全：传输层与应用层数据采用JSON格式封装，敏感指令（如控制指令）添加简单校验（时间戳+校验位），防止非法篡改。
- 接口安全：后端API接口添加请求频率限制（≤10次/秒），避免恶意请求攻击。

#### 4. 可行性确认
- 技术可行性：Vue3+SpringBoot均为成熟开源框架，社区支持完善，开发成本低；MySQL适配数据存储需求，与SpringBoot无缝集成，技术栈无壁垒。
- 资源可行性：前端开发可基于Vue3生态组件快速搭建页面，后端可复用MQTT客户端SDK对接传输层，硬件与传输层已完成调试，数据交互协议明确，无需额外改造。
- 成本可行性：开发工具（VS Code、IntelliJ IDEA）、框架、数据库均为开源免费，部署可采用轻量级服务器（如阿里云ECS入门级），成本可控。

#### 5. 需求共识
本需求文档经项目组确认，明确应用层需适配感知层与传输层的技术规范（如MQTT主题、数据格式），功能与性能指标需满足居家场景实际使用需求，后续开发严格按此文档推进，需求变更需经多方评审确认。

## 二、设计阶段
### （一）架构设计
#### 1. 系统整体框架
采用“前端-后端-数据库”三层架构，与感知层、传输层形成全链路协同，架构图如下：
```
用户层（手机/PC）→ 前端层（Vue3）→ 后端层（SpringBoot）→ 数据库层（MySQL）
                                          ↓↑
传输层（ESP8266+MQTT）→ 感知层（STM32+传感器+执行器）
```
- 前端层：负责用户交互与数据展示，通过HTTP请求与后端通信，通过MQTT客户端订阅/发布主题接收硬件数据、下发控制指令。
- 后端层：作为核心中转，负责接收前端请求、解析MQTT数据、与数据库交互、接口鉴权，同时处理跨层数据格式转换。
- 数据库层：存储用户信息、设备状态历史数据、告警日志、个性化设置等，提供数据持久化支持。

#### 2. 技术栈选型
| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue3 + Vite + Pinia + Axios + MQTT.js | Vue3提供组件化开发能力，Vite提升构建速度，Pinia管理全局状态，Axios处理HTTP请求，MQTT.js实现MQTT协议对接 |
| 后端 | SpringBoot 2.7.x + SpringMVC + MyBatis-Plus + Eclipse Paho | SpringBoot简化配置，SpringMVC处理接口请求，MyBatis-Plus简化数据库操作，Eclipse Paho作为MQTT客户端对接传输层 |
| 数据库 | MySQL 8.0 | 关系型数据库，适配结构化数据存储，支持索引优化，提升查询效率 |
| 部署 | 前端：Nginx静态部署；后端：Jar包独立部署 | 轻量化部署方案，降低运维成本，支持快速扩容 |

#### 3. 模块划分
- 前端模块：登录模块、首页状态展示模块、控制模块、数据查询模块、告警模块、设置模块。
- 后端模块：用户管理模块、MQTT通信模块、设备控制模块、数据存储模块、告警处理模块、接口鉴权模块。
- 数据库模块：用户表、设备状态表、历史数据表、告警日志表、个性化设置表。

### （二）详细设计
#### 1. 前端模块详细设计
##### （1）登录模块
- 逻辑：用户输入账号密码→前端校验格式→发送HTTP请求至后端→后端验证身份（查询数据库+密码解密）→返回登录结果→前端跳转首页（登录成功）或提示错误（失败）。
- 核心组件：登录表单（用户名输入框、密码输入框、登录按钮）、验证码组件（可选，防暴力破解）。
- 状态管理：通过Pinia存储用户登录状态（token），请求拦截器自动添加token至请求头。

##### （2）首页状态展示模块
- 逻辑：页面加载时，前端通过Axios请求后端获取当前设备状态，同时通过MQTT.js订阅“home/light/status”主题→实时接收硬件数据→更新页面展示（开关状态、亮度值、光照强度、时间戳）。
- 核心组件：状态卡片（显示开关/亮度/光照数据）、实时曲线图（展示近1小时光照强度变化）、设备在线状态标识。

##### （3）控制模块
- 逻辑：用户操作（开关/调节亮度/切换场景）→前端封装指令参数→通过MQTT.js发布至“home/light/control”主题→同时发送HTTP请求至后端记录操作日志→接收后端反馈的执行结果→更新页面状态。
- 核心组件：开关按钮、亮度调节滑块（5%-100%）、场景切换按钮（阅读/睡眠/观影）、操作反馈提示。

##### （4）数据查询模块
- 逻辑：用户选择时间范围→前端发送查询请求（携带时间参数+用户ID）→后端查询数据库历史数据表→返回数据→前端通过ECharts绘制折线图/柱状图展示。
- 核心组件：时间选择器、数据图表（支持切换图表类型）、数据导出按钮（导出Excel）。

##### （5）告警模块
- 逻辑：前端通过MQTT订阅“home/light/alarm”主题（新增告警主题）→接收告警数据→弹窗提示+更新告警列表→用户点击处理→前端发送处理请求→后端更新告警状态（未处理/已处理）。
- 核心组件：告警弹窗、告警列表（显示告警类型、时间、状态）、处理按钮。

##### （6）设置模块
- 逻辑：用户修改设置（亮度阈值、场景参数等）→前端校验参数合法性→发送保存请求→后端更新数据库设置表→返回成功结果→前端同步更新本地状态。
- 核心组件：阈值输入框、场景参数配置项、保存按钮、重置按钮。

#### 2. 后端模块详细设计
##### （1）用户管理模块
- 核心逻辑：提供用户注册、登录、信息查询、密码修改接口；注册时密码加密存储（MD5+随机盐），登录时生成JWT token返回前端，接口鉴权通过token验证用户身份。
- 核心接口：
    - POST /api/user/register：用户注册（参数：用户名、密码、手机号）
    - POST /api/user/login：用户登录（参数：用户名、密码，返回：token、用户信息）
    - GET /api/user/info：获取用户信息（header：token）

##### （2）MQTT通信模块
- 核心逻辑：初始化MQTT客户端→连接EMQX服务器→订阅“home/light/status”主题（接收硬件状态）和“home/light/alarm”主题（接收告警）→发布“home/light/control”主题（下发控制指令）；接收MQTT消息后解析JSON数据，同步至数据库和前端。
- 核心功能：
    - MQTT连接管理（自动重连、心跳维持）
    - 消息解析与转发（将硬件数据转换为前端可识别格式）
    - 指令封装（将前端控制指令转换为MQTT协议要求的JSON格式）

##### （3）设备控制模块
- 核心逻辑：接收前端控制请求→校验用户权限→调用MQTT客户端发布指令→监听指令执行反馈→记录操作日志→返回结果给前端。
- 核心接口：
    - POST /api/device/switch：灯光开关控制（参数：switchStatus（0/1））
    - POST /api/device/brightness：亮度调节（参数：brightness（5-100））
    - POST /api/device/scene：场景切换（参数：sceneId（1-3））

##### （4）数据存储模块
- 核心逻辑：接收MQTT模块解析的硬件状态数据→定时写入数据库（实时数据+历史数据）；接收前端查询请求→按时间范围+用户ID查询数据库→返回结构化数据。
- 数据同步策略：实时状态数据实时更新，历史数据按1分钟间隔批量写入（减少数据库压力），数据保留30天，过期自动清理。

##### （5）告警处理模块
- 核心逻辑：接收MQTT模块的告警数据→写入告警日志表→触发前端告警提示；接收前端告警处理请求→更新告警状态（未处理→已处理）。
- 告警类型：传感器故障、通信断连、亮度异常（超出用户设定阈值）、指令执行失败。

##### （6）接口鉴权模块
- 核心逻辑：基于JWT实现接口鉴权，通过拦截器拦截所有需要权限的接口→验证请求头中的token合法性→合法则放行，非法则返回401未授权。
- 免鉴权接口：登录、注册接口，公开演示数据查询接口（可选）。

#### 4. 接口规格设计
##### （1）HTTP接口（前端-后端）
采用RESTful风格设计，统一响应格式：
```json
{
  "code": 200, // 200-成功，400-参数错误，401-未授权，500-服务器错误
  "msg": "操作成功",
  "data": {} // 响应数据（可选）
}
```
核心接口示例：
- 登录接口：POST /api/user/login
    - 请求参数：{"username":"test","password":"123456"}
    - 响应数据：{"code":200,"msg":"登录成功","data":{"token":"xxx","user":{"id":1,"username":"test"}}}

- 亮度调节接口：POST /api/device/brightness
    - 请求参数：{"brightness":80}
    - 响应数据：{"code":200,"msg":"调节成功","data":{"brightness":80,"timestamp":"2024-06-01 10:00:00"}}

- 历史数据查询接口：GET /api/data/history?startTime=2024-06-01&endTime=2024-06-02
    - 响应数据：{"code":200,"msg":"查询成功","data":[{"timestamp":"2024-06-01 09:00:00","brightness":70,"light_intensity":180},...]}

##### （2）MQTT接口（后端-传输层）
沿用传输层定义的主题与数据格式，后端需适配以下规范：
- 订阅主题：home/light/status（状态数据）、home/light/alarm（告警数据）
- 发布主题：home/light/control（控制指令）
- 数据格式：JSON格式，字段与传输层一致（如控制指令：{"cmd_type":2,"param":80,"timestamp":1718000100}）

### （三）设计确认
本设计文档基于需求分析结果，充分适配感知层与传输层的技术规范，明确了应用层各模块的逻辑、接口、数据结构，技术选型与架构设计满足性能与扩展性需求，可直接作为后续开发的技术依据。
